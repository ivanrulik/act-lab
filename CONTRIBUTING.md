# Contributing

Start from the next unlanded pull request in `docs/ROADMAP.md`. Open one focused
PR, link its roadmap entry, and list its acceptance criteria in the description.

## Commit and PR conventions

Use concise imperative commits. Prefix PR titles by subsystem, for example:
`sim: add deterministic UR5e task` or `data: record versioned MCAP episodes`.

Every PR description should contain:

- problem and scope;
- architecture or contract impact;
- verification performed;
- artifacts or screenshots when relevant;
- known limitations and deferred work.

Review `docs/DEFINITION_OF_DONE.md` before requesting review.
